## Summary

1. **Evaluation independence:** splits and purges are chronological and correct, but EVT-005 straddles validation and test. It contributes 24 validation positives and 1 test positive, and its aftermath drives 6 of the 9 logistic-regression false flags on test. The only fully unseen test event is EVT-002 (one event-zone).
2. **Forecast vs persistence:** on identical test rows, logistic regression has lower F1 than the 'any warning' persistence baseline (0.238 vs 0.364). On the unseen-event subset it ranks better (PR-AUC 0.265 vs 0.184) but detects less at its operating threshold (recall 0.148 vs 0.259, F1 0.235 vs 0.350) and flags the unseen event later. With one unseen event, **meaningful added early-warning value is not demonstrated.**
3. **Foundry transfer:** EVT-002 differs from the training event on almost every axis (indoor radiant-heat zone, higher baseline, smaller relative deviations, different context features). Observed differences and hypotheses are separated in section 3.
4. **Score interpretation:** scores are uncalibrated; the threshold came from a train-only model and was applied to a refitted model whose score distribution differs. Brier scores are reported only as properties of an uncalibrated score.
5. **Heat-index validity:** 9 raw readings exceed the NWS chart range (max 67.4 C). Cause: the simulator lets humidity stay high at ~42 C (implied dew points ~29-31 C). Values are preserved; a validity indicator now flags them in fusion and forecast outputs.

**Observed evidence**

- Baseline heat: the foundry reference heat index is 36.8 C vs 29.4 C for EVT-001 zones; its robust z in escalation is 1.5 vs 6.7.
- Fusion signal: mean escalation risk score 17.2 (EVT-002) vs 55.1 (EVT-001); environmental score 37.8 vs 83.8.
- Forecast score in escalation: 0.50 (EVT-002) vs 0.93 (EVT-001, in-sample).
- Context: every positive in the refit data (EVT-001 at S02, EVT-005 at S01-Z01) is an outdoor or semi-outdoor zone without radiant heat (`ctx_outdoor` = 1, `ctx_radiant_heat` = 0); EVT-002 is the opposite. In the logit contributions, these two context features alone move EVT-002 positives about 1.74 logit units below EVT-001 positives - the largest single difference.

**Hypotheses (not verified)**

- Relative-deviation features (robust z, CUSUM) are smaller in a zone that is always hot, so the same physiological load looks less anomalous; absolute exposure would matter more there.
- The model may have learned 'outdoor + large deviation' as the heat-risk pattern from a single training event.
- The heat index ignores radiant heat; a radiant-heat zone's true strain is under-represented by it (WBGT would capture it). This is a measurement limitation, not fixable by re-weighting.
- No foundry-specific thresholds were introduced; testing these hypotheses needs new, independent scenarios (e.g. a different simulation seed), not the current test labels.

- The NWS heat-index chart covers air temperatures up to 43.3 C (110 F) and heat-index values up to about 58.3 C (137 F). The previously reported 63 C value (EVT-001, S02, 2025-07-04) is beyond that range: the Rothfusz regression is being extrapolated.
- Root cause (simulation): heatwave forcing raises humidity together with temperature, and humidity is not constrained by temperature, giving dew points around 29-31 C at ~41-43 C - a combination that is rarely observed (the highest dew points ever recorded are about 35 C) and is a simulation artefact here. One flagged reading is an injected sensor spike (intended).
- **Fix applied (non-destructive):** `src/features/quality.py::heat_index_validity`; risk fusion now outputs `heat_index_observed`, `heat_index_validity`, `measurement_flags`, `alert_relies_on_extrapolated_heat_index`, adds a caution to explanations and to the environmental explanation note; forecasts add a limitation note. Raw values are not clipped, heat index is not relabelled, and scores/classes are unchanged (the environmental absolute component already saturates at 51 C, so extrapolated magnitude adds no extra score).
- **Deferred (simulation correction):** constrain humidity by a dew-point cap in `src/data_generation/environment.py`. Not applied now because it would regenerate all data and change every downstream result; it should be done together with a fresh, independent evaluation.
